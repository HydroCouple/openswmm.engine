# A3 (Subcatchment Water Age) — Scoping Findings

**Status:** scoping only. **No code written.** Produced 2026-08-17 after H4
landed (`8b5b3ef5`), when the roadmap's dependency column showed H5 blocked
behind A4 → A3.
**Plan:** `WATER_AGE_TRACKING_PLAN.md` §3, §7 A3.
**Why this exists:** the survey below changed the shape of A3 enough that
implementing from the plan text alone would have built the wrong thing. It
also raised three decisions that want answers before code, not during it.

---

## 1. Why A3 is next

H5 (watershed + LID temperature) lists deps **"H1, A4 block"**; A4 (LID
layer age — *the generic per-layer species block heat reuses*) is ⬜ and
depends on A3 ⬜. Building a heat-only per-layer structure now is precisely
the "no interim structure built twice" that A3, A4 and H5 each warn against
in their own rows. A3 is also H5's watershed twin, so it builds the pattern
once with age's simpler semantics — no fluxes, no constants, no unit system.

## 2. Findings that change A3's shape

### 2.1 The obvious state field is DEAD — do not build on it

`ctx.subcatches.ponded_depth` (`SubcatchData.hpp:265`) exists and is **never
written by any solver** — only read at `SWMMEngine.cpp:2528` and `:6426`.

The real per-subarea water lives in the **runoff solver's own SoA**:
`RunoffSolver::depth_imperv0 / depth_imperv1 / depth_perv`
(`Runoff.hpp:86-88`), mutated by reference inside `processSubarea`
(`Runoff.cpp:346`, writes at `:458, 466-474`). The area-weighted volume
expression already exists, in the mass balance at `SWMMEngine.cpp:3664-3666`:

```
(depth_imperv0*f0 + depth_imperv1*f1 + depth_perv*fp) * area
```

**That is the volume an age state must be volume-weighted against.** A naive
`ctx.subcatches.ponded_depth`-based implementation would have divided by
zero everywhere and looked plausible doing it.

### 2.2 Run-on water carries no age today — a real gap A3 must close

`addWetWeatherLoads` skips any subcatchment whose outlet is another
subcatchment, because `outlet_node < 0` (`QualityRouting.cpp:311-312`).
Meanwhile the FLOW path adds run-on: `q = q_runoff + q_runon` at
`SWMMEngine.cpp:1948-1958`, while the quality/age path at
`QualityRouting.cpp:316` uses `runoff` alone.

So a two-subcatchment cascade — **the plan's own A3 verify criterion** —
currently delivers water to the node with no age attached from the upstream
subcatchment. This asymmetry is the A3-shaped instance of the family that
has now bitten four times (R4, E5a, A1a, H1): a pathway that the flow side
knows about and the quality side does not.

### 2.3 Subarea depths are NOT in the hotstart

No `depth_imperv*` reference anywhere in `HotStartManager.cpp`. So
subcatchment age will not survive a restart even after A3, unlike node/link
age (A2a's native V3). **Whether that is acceptable is a decision** — see
§3.3.

### 2.4 Snow reaches runoff one indirection later

Melt does not write `subcatches.runoff`; it goes through
`snow_net_imperv` / `snow_net_perv` (`SubcatchData.hpp:465, 474`, built at
`SWMMEngine.cpp:1577-1603`) and is consumed as subarea precip at
`Runoff.cpp:543-548`. SWE itself is `wsnow` in the Snow SoA (`Snow.hpp:68`),
**stride 3**, subarea 0 = `SNOW_PLOWABLE`. Plan §8's open item — the
`WATER_AGE_SNOW` default — is therefore a question about whether the pack
holds age or merely passes it through.

### 2.5 The structural analogue to copy

`ponded_qual` (`SubcatchData.hpp:346`) — per-(subcatch, pollutant) MASS,
stride np, with a complete-mix update at `SWMMEngine.cpp:2540-2568` that
already does mass in → infiltration loss → outflow loss → residual carried
forward. **That is the shape an age-volume accumulator should mirror**, not
the node-store pattern.

### 2.6 The placeholder to retire

`SWMMEngine.cpp:4358-4377` fills `snap.subcatch_quality` and leaves the age
column at 0 with a comment naming A3. Snapshot stride is `nr_s`, source
stride `np_s`, age column index `np_s` — same layout as the link write at
`:4346-4348`. Retiring this is in-changeset work (lesson 21), and both the
`.out` and the GeoPackage now publish that zero, so it is user-visible.

## 3. Decisions wanted BEFORE implementation

### 3.1 Where does subcatchment age live?

- **(a) One age per subcatchment**, volume-weighted over the three subarea
  depths. Simple, matches how `runoff` is already a single per-subcatchment
  rate, and is all the plan's cascade gate needs.
- **(b) One age per SUBAREA** (three per subcatchment), mirroring the depths
  themselves. Physically finer — impervious water is younger than pervious —
  but triples the state and has no consumer today.

I lean (a), with (b) noted as the refinement A4's per-layer block may make
natural. **Recorded as a question because it sets the state layout, and
changing it later is the churn D-UT10 exists to avoid.**

### 3.2 Does run-on carry age in A3, or is it deferred loudly?

§2.2 makes this a real gap rather than a nicety. Closing it means the age
path stops keying on `outlet_node >= 0`. **My recommendation: close it in
A3**, because the plan's own verify criterion is a two-subcatchment cascade
and a deferral would make that gate untestable — the lesson-59 shape (a gate
whose subject the deck cannot reach).

### 3.3 Hotstart persistence — now, or an owed row?

A2a gave node/link age a native V3 record. Subcatchment age has no
equivalent and §2.3 shows the underlying depths are not persisted either.
Adding it means touching the hotstart format again. **Recommendation: defer
with a named error/warning and record the row**, since persisting an age
whose water volume is itself not persisted would restore a mean over a
volume that no longer exists.

## 4. Suggested gate set (for whoever implements)

1. **Two-subcatchment cascade** — the plan's criterion. Upstream drains to
   downstream; the downstream subcatchment's runoff age must be the
   volume-weighted mix, and the arithmetic should be chosen so no wrong
   answer lands on the right number (lesson 26).
2. **Run-on carries age** — the §2.2 gap, asserted directly. This is the
   gate that fails today.
3. **A2b placeholder retired** — the `.out` subcatchment age column reads a
   real value, by NAME not index (lesson 40).
4. **Volume weighting is live** — two subareas at different depths must not
   give the unweighted mean (lesson 61: "it moved" is not a magnitude
   observer).
5. **Setup assertion on every deck** that the subcatchment actually produced
   runoff, or gates 1–4 pass vacuously (lesson 36).
6. **Snow leg** or an explicit deferral naming the phase (plan §8's
   `WATER_AGE_SNOW` question).

**Lesson 59 applies sharply here:** several of these guard code that only
runs on a deck with run-on configured, or with two subareas at different
depths. The deck has to reach the branch.

# R2 verification, 2026-10-05

The task source hashes and patch identify the changes tested on base commit 546af5d8670a6770451a7345cd68c71bb36a8bd0. The isolated source was extracted from that commit, patched with task.patch, and supplied with the new receiving unit test. Local `before/` snapshots and `isolated/source`, build directories and binaries are intentionally excluded from version control because the shared checkout also contains unrelated work.

Both engines used the same Ninja Release configuration: 2D, HDF5, GeoPackage and unit tests enabled; bundled vcpkg arm64-osx dependencies and the existing thin-LTO settings. The separate baseline library was saved before applying the task patch. Each saved CLI was linked to its own absolute engine library and signed. `isolated/corpus/provenance.json` records both library hashes and actual dynamic links; the engines are different files with different hashes.

`verify.py` runs the five selected engine suites and the groundwater gates (add the argument `isolated` for the isolated build). `compare_corpus.py` runs only the current explicit 25-deck parity manifest, using absolute executable paths and nonzero-exit/missing-output checks. It intentionally avoids the recursive census of generated fixtures in the shared checkout. `api_census/compare.py` separately compares raw-double depth, infiltration rate, accepted depth and total volume trajectories for six ordinary infiltration methods in US/SI units, both enabled and OFF. It records sample counts and input decks, so an empty census cannot count as success.

Final results: isolated 125/125 tests, all groundwater gates, 25/25 corpus outputs and 24/24 API trajectories. Shared checkout: 128/128 tests and all gates; the three extra hotstart tests are unrelated local work. Full log files and JSON summaries are retained. The model inputs, pending-tracer hotstart and two actual HDF5 results are controlled test artifacts, not calibrated field models. `inspect_output.cpp` reads the actual HDF5 fields with the same HDF5 library; `output_fields.json` distinguishes finite zero from unavailable capacity/allowance/refresh values under OFF.

The source-level numerical contract and limitations are in `plans/SURFACE_PROCESS_R2_IMPLEMENTATION_2026-10-05.md`. GUI checks, screenshot and packaged-library hashes are in the companion GUI repository's `tests/gui/data/surface_r2_out/`. The GUI checks exercise the shared checkout, not an independently rebuilt GUI archive.
